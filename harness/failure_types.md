# 실패 원인 유형

유형이 정해져 있어야 같은 실수가 반복되는지 셀 수 있습니다. 새 유형은 기존 유형으로 설명되지 않을 때만 추가합니다.

| 코드 | 이름 | 예 |
|---|---|---|
| `silent-drop` | 결과 무단 생략 | 목록을 상위 N개로 자르면서 생략 사실을 숨김 |
| `unverified-done` | 미검증 완료 보고 | 실행하지 않았거나 사용자 관점 조건을 확인하지 않고 완료라고 보고 |
| `context-loss` | 맥락 손실 | 이전 결정·작업을 잊고 다르게 구현 |
| `scope-creep` | 범위 이탈 | 지시서에 없는 파일·기능을 변경 |
| `duplicate-impl` | 중복 구현 | 이미 있는 기능을 다시 만듦 |
| `unfounded-claim` | 근거 없는 주장 | 원문·데이터에 없는 사실을 결과에 포함 |
| `wrong-assumption` | 잘못된 가정 | 데이터 형식·환경·API를 확인 없이 가정 |
| `env-config` | 환경·설정 문제 | 경로, 인코딩, 권한, 의존성 |
