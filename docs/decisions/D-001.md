# AI는 제안하고, 코드가 원문과 대조해 확정한다

## 배경
career-matching에서 규칙을 많이 걸면 표현이 조금만 달라도 깨졌고, 판단을 Bedrock에 맡기면 결과를 설명·검증할 수 없었다.

## 선택지와 이유
- 규칙만: 재현 가능하지만 표현 변화에 약함 → 비교 기준(베이스라인)으로만 사용
- 모델만: 유연하지만 근거 추적 불가
- **선택: 모델(또는 사전)이 기술·근거 문장·필수/우대를 제안하고, 코드가 근거의 원문 존재·기술 포함·판정 일치를 검사해 확인/불확실/제외로 나눈다.** 집계와 추천 이유는 확인된 근거로 코드가 만든다.

## 영향
- 발표의 "어떻게 검증했나"에 대한 답이 구조 자체가 된다.
- 개발 과정(구현 → check → 승인)과 하네스 개선(후보 → 승격 조건 → 승인)에도 같은 구조를 쓴다.
