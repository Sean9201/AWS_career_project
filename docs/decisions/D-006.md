# 사전은 사람이 검증하되, 검토 노동은 "자주 새로 나오는 용어"에만 쓴다

채택: 2026-11-07, 사용자가 [[review-001]]과 함께 승인. 2·5단계는 코드에 반영됨(`dictionary_gaps`가 2건 이상만 보여주고 숨긴 수를 표시, `skills.json`의 `_ignore`). 3·4-a는 아직 사람이 수작업(Bedrock 미사용).

## 배경
표준화 사전(`data/skills.json`)은 어떤 표기가 같은 기술인지의 기준이다. 모든 새 용어를 사람이 영원히 검토해야 하는지, 어느 정도 지나면 알아서 되는지 물음이 나왔다.

## 결정 (제안)
완전 자동화는 하지 않는다. 대신 사람이 볼 양이 줄어들도록 단계를 나눈다.

| 단계 | 누가 | 조건 |
|---|---|---|
| 1. 자동 매칭 | 코드 | 사전의 표준명·별칭과 일치하면 사람 개입 없음 |
| 2. 후보 큐 | 코드 | 사전 밖 태그·토큰은 큐에 쌓임. **공고 2건 이상**에서 나온 것만 검토 대상. 1건짜리는 "불확실"로 두고 집계에 넣지 않으므로 수치에 영향 없음 |
| 3. 분류 초안 | AI (Bedrock) | 각 후보를 기술/비기술, 별칭/새 표준명, 추천 표준명으로 초안 작성 |
| 4-a. 새 표준명 추가 | 코드 (조건부 자동) | 기존 행에 영향이 없으므로, AI 확신이 높고 제외 목록에 없으면 자동 반영 허용. 반영 이력은 남김 |
| 4-b. 별칭으로 합치기 | **사람 승인 필수** | 기존 집계 숫자가 바뀌는 변경(예: Continuous Integration → CI/CD). 클릭 한 번이지 조사가 아님 |
| 5. 제외 목록 | 사람 | 성향·일반 단어는 `_ignore`에 넣어 다시 뜨지 않게 함 |

## 왜 노동이 줄어드는가
- 검토량은 "새로 자주 나오는 용어" 수에 비례하고, 그 수는 공고가 쌓일수록 급격히 준다(앞쪽 수백 건에서 흔한 기술은 거의 다 나온다). 29건에서 48개 후보가 나왔지만, 다음 100건에서는 그보다 훨씬 적을 것으로 예상한다. 실제 감소 폭은 2차 검토 때 기록한다. 1라운드 실측: 제공자 태그 72개 중 사전 밖 2건 이상 35개를 검토, 반영 후 큐 0개(제외 25, 1건짜리 1).
- 공개 기술 분류(예: ESCO, Lightcast Open Skills — 영문, 이용 조건 확인 필요)로 사전을 시드하면 처음부터 수천 개가 들어와 새 후보가 더 준다. 한국어 표기는 별도로 쌓아야 한다.
- 대회 기간에는 2~3라운드면 충분할 것으로 본다. 1라운드는 [[review-001]].

## 영향
- `skills.json`에 `_ignore` 목록 추가. 후보 큐는 run.json의 `dictionary_gaps`를 그대로 쓰되 2건 이상만 표시.
- 사전은 git으로 버전이 남으므로 "사전 v1 vs v2" 재현율을 같은 정답셋에서 비교할 수 있다.
- 임베딩은 D-002대로 "가까운 표준명 후보 제시"에만 쓴다.
