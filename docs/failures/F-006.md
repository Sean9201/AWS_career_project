# 같은 공고가 사람인·잡코리아 양쪽에서 들어와 두 번 세어짐

## 증상
화면 점검에서 MySQL 근거 목록에 "(주)럭스로보 · 백엔드 개발자 경력직 채용 (3년 이상)"(saramin_kr)과 "주식회사 럭스로보 · 백엔드 개발자 경력직 채용"(jobkorea_kr)이 같은 문장("RDBMS(MySQL/PostgreSQL) 이해 및 최적화 경험")으로 각각 나왔다. 수요 표의 필수·언급 건수가 1건씩 부풀려진다. 30건 중 1쌍 확인.

## 원인
`skillpath/sources/techmap_adapter.py`가 공고 URL로만 중복을 제거한다. 한 회사가 여러 채용 사이트에 올린 같은 공고는 URL이 달라 통과한다. Techmap의 `isDuplicate=false` 필터도 이 경우를 잡지 못했다.

## 수정
`skillpath/dedupe.py` 추가. 회사명에서 법인 표기(㈜, (주), 주식회사 등)와 기호를 뺀 키가 같고, 자격요건·우대사항 문장 집합의 겹침(Jaccard)이 0.6 이상이면 같은 공고로 묶는다. 정확 일치를 쓰지 않은 이유: 잡코리아 판은 마지막 우대 문장 뒤에 "복지제도 전형절차"가 붙고 주요업무 제목이 사라져 본문이 완전히 같지 않았다. 본문이 3문장 미만(이미지 공고)이면 제목이 같을 때만 묶는다. 대표는 섹션이 더 많이 인식된 쪽, 같으면 먼저 게시된 쪽이고, 나머지 출처는 `also_at`에 남겨 화면에 "같은 공고 [jobkorea_kr]"로 표시한다.

결과: 30건 → 29건, 분석 대상 23건 → 22건. 럭스로보 공고 1건이 합쳐져 MySQL·Docker·PostgreSQL·Kubernetes·Go·AWS 필수 건수와 Kafka·Redis 우대 건수가 각 1씩 줄었다.

## 재발 방지
- 회귀 테스트: `test_same_job_on_two_sites_with_portal_formatting_noise`, `test_same_company_different_jobs_stay_apart`, `test_keeps_the_copy_with_more_sections_and_lists_the_rest`
- 정답셋을 만들 때 `also_at`이 있는 공고는 대표 1건만 라벨링.
- 남은 한계: 회사명이 아예 다르게 적힌 재게시(예: 헤드헌팅사 명의)는 못 잡는다. 표본이 늘면 회사명 없이 본문 겹침만으로 후보를 뽑아 사람이 확인하는 단계를 검토.
