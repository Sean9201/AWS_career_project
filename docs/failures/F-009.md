# "Vue.js"의 ".js"가 JavaScript로 집계됨

## 증상
실제 공고 22건 기준 화면에 JavaScript 우대 3건·언급 6건으로 보였다. 사전 v2([[review-001]]) 반영 전후 수요 표를 비교하다가 우대 1건·언급 3건으로 줄어든 것을 발견했다. 줄어든 3건은 본문에 JavaScript가 없고 Vue.js·Next.js만 있던 공고였다. 2026-11-05~07 사이 사용자에게 틀린 숫자가 보였다.

## 원인
`skillpath/skills.py`의 별칭 경계 검사가 앞뒤 영숫자만 봤다. 그래서 "JS" 별칭이 "Vue.js"의 "js"에 붙었다("." 은 경계로 통과). 사전 v1에는 Vue.js·Next.js가 없어 더 긴 별칭이 그 자리를 먼저 차지하지 못했다. 원인 유형: wrong-assumption — 경계 규칙을 실제 공고 본문으로 확인하지 않고 가정했다.

## 수정
별칭 바로 앞 글자가 "."이면 접미사로 보고 매칭하지 않는다 (`(?<![A-Za-z0-9.])`). 사전에 없는 "Three.js", "Nuxt.js"는 이제 아무것도 매칭되지 않고(불확실로 남음), "HTML/CSS/JS"의 JS는 여전히 JavaScript다.

## 재발 방지
- 회귀 테스트: `test_js_suffix_is_not_javascript`
- 두 글자 별칭(JS, TS, CS 등)을 넣을 때는 실제 공고 본문에서 매칭 결과를 한 번 훑는다. 가정 전에 표본을 보는 [[R-003]] 후보와 같은 취지.
