# 프로젝트 목적과 맥락

모든 작업의 판단 기준이 되는 노트입니다. 설계나 범위가 헷갈리면 여기로 돌아옵니다.

## 한 줄 목적

**채용공고에 나타난 기술 수요를 근거 있는 학습 경로로 바꾸는 서비스.**

- **주목적은 개인 추천 서비스**다. 사용자가 목표 직무(·지역)를 고르고 보유 기술을 입력하면, 부족한 역량과 공부할 교육과정을 근거와 함께 보여준다.
- **시장 분석은 그 추천의 근거**로 쓴다. "목표 직무 공고 N건 중 X%가 이 기술을 필수로 요구한다"가 "왜 필요한지"의 답이 된다.
- 핵심은 화려한 챗봇이 아니라 **데이터에서 추천까지 이어지는 검증 가능한 흐름**이다.

## 강의에서 정리한 원래 맥락 (승현 메모)

> 국내 채용·직무 데이터를 AI로 분석하여 산업·직무·지역별 AI·클라우드 인재 수요와 요구역량을 도출하고, 이를 교육과정 및 개인별 학습경로 추천까지 연결하는 AI 기반 시스템 구현

- 문제: 기술 요구사항이 계속 많이 생겨나고, 회사마다 공통된 요구사항을 찾기 힘들다 → 어떤 교육과정을 설계·선택할지 판단하기 어렵다.
- 흐름: 공고를 가져온다 → 공고 문장에서 기술 역량을 추출한다.
  - 기술명만 뽑는 게 아니라 **어떤 문장에서 근거했는지**, **필수인지 우대인지**, **같은 맥락의 키워드를 하나의 워딩으로 통합**할 수 있는지.
- 직무·산업별로 어떤 역량이 많이 수요가 있는지 분석하고, **국가직무능력표준(NCS)**과 연결한다.
- 결과를 통해 교육과정을 추천한다. **AWS 위에서(AWS 서비스로) 추천 시스템을 만든다는 뜻**이다. 추천 대상이 AWS 교육으로 한정되는 것은 아니다. (2026-11-05 승현 확인)
- 최종 화면: **무엇이 필요하고, 왜 필요하고, 무엇을 공부해야 하는지** 확인할 수 있어야 한다.
  - 목표 직무에서 가장 많이 등장하는 기술 → 이런 게 필요하기 때문에 → 이런 교육이 필요하다.
- AI와 AWS 사용: 임베딩·벡터로 유사한 문서나 근거를 찾았다고 정확한 매칭이 보장되지 않는다. **검색 결과를 검증하고, 불확실한 건 불확실하다고 표시한다.**
- 목표 사용자를 정하고 **작은 샘플로 전체 흐름**을 먼저 만든다.
- 발표에서 설명해야 할 것: 어떤 데이터를 분석했는지, 어떤 근거로 이 역량이 필요한지, 어떤 맥락으로 교육과정이 연계됐는지, 왜 하필 이 교육과정을 추천했는지. **그 근거와 그 사이의 검증**이 중요하다.

## 대회 정보

- 대회: AI분야 부트캠프 통합 경진대회, 주제 "AWS 클라우드 기반 채용시장 기술역량 자동 분석 및 교육과정 추천 AI 에이전트 개발"
- 발표: **2026-11-25**, 발표 15분 + 질의응답 7분
- 심사 (각 20점): 문제해결력, 현장 적용성, 창의성, 전달력, AWS 기술 활용도·팀워크
- 주제 자료가 제시한 흐름: 데이터 수집(고용24·NCS·고용행정통계) → 근거 문장과 함께 기술 추출 → 표현 표준화 → 직무·산업별 분석과 NCS 연결 → 교육과정 추천(이유·링크·난이도·선수지식 포함)
- 발표에서 반드시 답할 질문 3개
  1. 어떤 데이터를 분석했나요?
  2. 어떤 근거로 이 역량이 필요하다고 판단했나요?
  3. 왜 이 교육과정을 추천했나요?

## 범위의 의미

- 시장 분석은 **대한민국 전체 수요의 대표값이 아니다.** 같은 데이터셋·직무·지역·기간 안의 비율로만 말한다.
- 표본은 직무 3~4개(예: 백엔드, 데이터, 클라우드/DevOps, AI)마다 같은 데이터셋에서 100건 이상을 목표로 한다.

## 열린 질문

- NCS 연결 범위: 공고 기술 → NCS 분류 → 해당 NCS 코드의 교육과정.
- 추천할 교육과정 데이터 출처 (고용24 훈련과정 API 등, 이용 범위 확인 필요).

## 정리된 질문

- "AWS 교육과정 추천" = AWS 서비스로 교육과정 추천 시스템을 구현하라는 뜻. AWS 교육(Skill Builder)만 추천하라는 뜻이 아님. (2026-11-05)
